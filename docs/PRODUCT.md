# 阿碳日报 · 产品设计

> 适用于 **1.2.1**。安装方法见 [README](../README.md#安装)，版本变更见 [更新日志](CHANGELOG.md)，联系方式见 [官网](https://atandaily.cn/)。
>
> 本文只讲产品与使用：功能设计、界面入口、任务目录、飞书机器人与运行机制。源码结构、构建与贡献约定见 [README 的「反馈与贡献」](../README.md#反馈与贡献)。

## 1. 产品定位

给每个选题一个目录、一份任务细节和一份文件索引，剩下的事按计划自动发生。

阿碳日报把「一个长期跟踪的选题」当成一个可持续运行的自动化任务：用户写清楚目标、数据来源和输出要求，插件按设定时间把它跑成一期带时间戳的报告，并把报告推给指定的人。

| 名词 | 含义 |
| --- | --- |
| 选题 / 任务 | 工作区下的一个文件夹，文件夹名就是任务名 |
| 任务细节 | `task-detail.md`：目标、数据来源、口径、边界，用户维护 |
| 执行清单 | `.meta/task-pipeline.json`：pipeline 命令 + scripts / cache 清单 |
| 数据契约 | `.share/task-schema.json`：这期报告要哪些数据、什么类型、怎么呈现 |
| 一轮（run） | 一次完整执行：取数 → 写 `report.json` → 渲染最终文档 → 记运行记录 → 推送 |
| 最终文档 | 任务根目录下的 `<任务名>-<时间戳>.pdf` 或 `.png`；上一轮在开跑前移入 `history/` |
| 执行规则 | `atan-daily-run` skill，随插件注册，所有任务共用一份 |

## 2. 功能设计

- **定时执行**：执行时间可以用日常说法（「每天 9 点」「每周一和周四 8 点」）、五段 cron 表达式，或者干脆只手动执行；每个任务单独设置 IANA 时区。
- **页面公告**：标题下方是公告位，内容来自任务服务的 `GET atan-daily/announcement`（Host 转发 `/api/atan-daily/announcement/current`）。默认只显示一行标题，有正文时点「展开」看全文（正文超过 240px 在卡片内滚动）；接口返回 `enabled=false`、没配服务地址或接口异常时整块消失，不影响任务列表。运营在 `atan-admin-web` 的「阿碳日报 → 公告管理」里开关与编辑，保存后 5 分钟内生效。
- **报告推到飞书**：页面标题行进入「机器人管理」，手机扫码即可创建飞书机器人；每个任务卡片右下角显示目标机器人图标与「推送管理」，可以只推一个机器人，也可以同时推给多个。
- **一任务一目录**：每个选题就是一个文件夹，用户只写 `task-detail.md`，`.meta/task-pipeline.json` 登记执行命令、缓存与脚本；两者分开维护，改任务内容不用改代码，也不会动到执行清单。
- **共用执行规则是一个 skill**：目录骨架、执行要求与输出约定统一放在 `atan-daily-run` skill 里；每次执行由指令要求会话先加载它，不再往每个任务目录复制一份模板。
- **一份数据 + 一份最终文档**：每轮把 `report.json` 写到 `.meta/build/<runId>/`，插件再按任务设置渲染成 `<任务名>-2026-10-31_21-30-00.pdf` 或 `.png`。最终文档放任务根，上一轮整组移进 `history/`；同一秒内重跑自动加 `-2`、`-3`。
- **数据契约 + 模板渲染**：任务首轮生成 `.share/task-schema.json`，写清「这期报告要哪些数据、什么类型、怎么呈现」。契约分两层：`properties` 定义数据字段，`x-blocks` 定义版面（标题、段落、指标卡、表格、图表、分栏与卡片），每个块用 `source` / `fields` 引用字段。契约不可用或数据不合规时回退成「原始数据」报告，报告照出、原因写在报告顶部。
- **展示可微调**：在任务会话里直接说要求（字号、颜色、间距、图高、点径、数据表显隐，或把某块换成柱状图/折线图）。`atan_daily_report_tune` 会把要求编译成唯一草稿，先给改动后预览；继续说就继续改，确认后才写 `.share/task-display.json` 与 `.share/task-schema.json` 并重渲染。草稿落盘但 commit/discard 后删除，不随任务上传。
- **主题可切换**：正文、表格、指标卡与图表 chrome 共用一套设计令牌，内置默认与紧凑两套主题；任务在 `report.json` 里指定 `theme`，未注册的名字回退默认。
- **图表随窗口缩放**：折线、柱、面积、饼、散点、迷你线都由图表的服务端渲染出内联 SVG，报告是零脚本单文件；缺数据处断线，不插值。
- **会话方式可选**：默认每次执行都由 Host 新建一个普通会话，旧会话自动归档，侧栏里能点进去看完整过程；在编辑抽屉里关掉「每次执行打开新会话」后，任务会复用同一会话，让上下文跨轮次延续。
- **权限级别可选**：编辑抽屉里按任务选择「工作区内修改」（默认，只能读写工作区内的文件）或「完全权限」（可读写任意路径）；下一次执行即生效。
- **运行历史**：每次执行的状态、耗时、报告、会话与错误都有记录，可按任务设置保留天数（默认 7 天，`0` = 永久）。
- **并行执行**：不同任务的运行同时进行，一个长任务不会挡住其他任务的到点执行；同一个任务仍然互斥（重叠的那次记为跳过），补跑只补最近一次错过的执行。
- **统计与搜索**：列表顶部显示任务总数、已启用、执行中、异常任务；搜索按名称或详情实时过滤，每页 10 条。
- **跟随 DSH 主题**：颜色、圆角、阴影、动效全部来自 `--dsw-*` 语义令牌，浅色与深色模式零改动。

## 3. 任务上传与任务仓库

需要同时部署 `atan-admin-server` 与 `atan-admin-web`。插件 Host 通过任务仓库地址访问任务管理服务（协议 + host + 端口），默认是 `https://atandaily.cn`（不写端口即 443），也可以在 `cordis.patch.yml` 里改成自己的地址：

```yaml
- id: atan-daily
  config:
    serverBaseUrl: http://10.0.0.12:8080
```

页面「工作区」下方的「任务仓库地址」始终显示当前生效的地址（没改过时就是默认的 `https://atandaily.cn`），点「修改」可直接改：保存的值写进 `settings.json` 并优先于 yaml，改完立即生效、不用重启；留空表示回到默认地址，在 yaml 里显式写 `serverBaseUrl: ''` 才会关掉上传与任务仓库。内置域名只走 https——旧版本存下的 `http://atandaily.cn` 会在读取时自动升级，自建地址则按填写值使用。「联系作者」按钮不依赖任何部署配置，直接打开[官网主页](https://atandaily.cn/)（QQ 群在「如何联系」一节）。

服务不可达时，上传与任务仓库会提示“任务仓库暂不可用”，本地任务列表不受影响。

- **上传任务**：编辑抽屉底部「上传任务」→ 三步向导（文件 / 确认信息 / 预览 `task.json`）。上传包是 `.share/` 下的三份文档加 `charts/*.mjs`，每份文件只有路径与内容两个字段；任务名称来自本地任务，简介与标签来自 `.share/task-schema.json` 的 `x-summary` / `x-tags`；取数脚本、缓存与历史报告不上传。打包时做确定性检查（路径、非法字符、体积、扩展名、图形脚本的危险 API），恶意性由管理端人工审核。上传身份取自 DSH 登录的 DeepSeek 账号（uid 必带，脱敏邮箱 / 手机号 / 实名认证 ID 有就带）；未登录不可上传，实名认证 ID 取不到时不阻断。
- **任务仓库**：任务列表标题行、机器人管理左侧「任务仓库」→ 右侧抽屉；卡片上的「任务详情」只读展示任务包正文、默认参数与报告 Schema（不含提交者身份）；加载后复制任务详情与 Schema 到本地任务目录，执行时间 / 时区可当场修改。
- **审核**：在 `atan-admin-web` 的「阿碳日报 → 上传任务管理」中通过 / 拒绝；不做通知。

## 4. 使用方式

| 你想做什么 | 如何操作 |
| --- | --- |
| 选择工作区 | 插件里的「工作区」就是 DSH 的工作区，只能在已注册的工作区之间切换。首次打开时点「使用建议工作区」（默认是 DSH 默认工作区的父目录下的 `atan-daily`，如 `C:\Users\<你>\Documents\deepseek-harness\atan-daily`），或点「选择工作区…」：弹窗里可搜索已有工作区，也可以在下方输入目录地址新建（不存在时创建目录并注册为工作区）。没选之前任务列表为空、不能新建任务。 |
| 新建选题 | 点「新建任务」，填写名称与任务详情（目标、数据来源、输出要求），再设置执行时间；任务详情写入 `task-detail.md`。 |
| 改任务细节 | 点任务行「编辑」打开右侧抽屉，任务详情上方的「任务名称」可以改名；改名会把任务目录一起改成新名字（正在执行或目录重名时保存会失败）。任务详情写入 `task-detail.md`，只有内容变化时才提交，下一次执行生效。 |
| 设置执行时间 | 「按说法」写日常表达，「按 cron」写五段表达式，「仅手动」则只能点「执行一次」。 |
| 改会话方式 | 点任务行「编辑」打开右侧抽屉，切换「每次执行打开新会话」：默认打开，每轮都从空会话开始；关掉后复用上一次会话。 |
| 改权限级别 | 同一个编辑抽屉里选「权限级别」：默认「工作区内修改」，只能读写工作区内的文件；需要跨目录读写时才切到「完全权限」。无人值守运行不会弹审批，工作区外的操作会被拒绝。 |
| 改文档格式 | 编辑抽屉里选 PDF 或 PNG：PDF 适合长文档/打印，PNG 适合短报告；PNG 超过约 9 页 A4 会截断。没有 Chrome/Edge 时不能选 PNG。 |
| 临时跑一轮 | 点任务行上的「执行一次」，完成后会跳到本轮运行的会话（新建或复用）。 |
| 查看报告 | 最新一轮最终文档在任务目录根：`<任务名>-<时间>.pdf` 或 `.png`；中间件在 `.meta/build/<runId>/`。 |
| 看历次报告 | 任务目录根下只有最新一轮，更早的最终文档都在 `history/` 里。 |
| 看执行过程 | 点「会话」进入该任务的会话；已有会话会直接打开。 |
| 改工作区 | 页面顶部点「选择工作区…」：列表默认只显示 atan-daily 用过的工作区（目录下有 `.task/`），可搜索、可勾选「显示全部工作区」；输入目录地址会创建并注册成新的工作区。切换后任务列表变成目标工作区的任务；运行中不允许切换。 |
| 接入机器人 | 标题行「机器人管理」→「接入机器人」→ 填名称（接入后不可改）→ 生成二维码 → 手机扫码。接入后会给扫码人发一条欢迎消息，用来验证发送链路。 |
| 把报告发到飞书 | 任务卡片右下角点「推送管理」打开抽屉，一行一个机器人，逐个开启/关闭；卡片上显示目标机器人的平台图标（最多 5 个）。抽屉顶部的「报告推送」总开关可以暂停发送，机器人选择会保留；从一个都没选变成有选中时，推送会自动打开。 |
| 断开机器人 | 机器人卡片「移除」。飞书里的应用不会跟着删；确认框里给出两步路径：先由企业管理员在管理后台停用，再由应用所有者在开发者后台删除（从未发布过的应用可直接删）。 |
| 停掉某个选题 | 关闭任务行上的开关；不会删除文件和历史。 |

## 5. 任务目录结构

任务目录长这样：

```text
<工作区>/
├── .task/
│   └── task-list.jsonl        任务元数据（唯一权威）
└── A股 银行股息收集/           任务目录 = 任务名称
    ├── .share/                随任务上传
    │   ├── task-detail.md     任务细节：目标、数据源、口径、边界（用户维护）
    │   ├── task-schema.json   数据契约：字段 + 版面
    │   ├── task-display.json  外观覆盖（可选）
    │   └── charts/            自定义图形脚本（.mjs，随任务上传）
    ├── .meta/                 本地运行资料，不上传
    │   ├── task-pipeline.json 执行清单：pipeline / scripts / cache
    │   ├── cache/   script/   稳定数据与脚本
    │   ├── display/           展示覆盖草稿（draft.json）
    │   ├── runs/              每次运行的 JSON 记录
    │   └── build/             每轮中间件：report.json / report.html；每轮结束只留最新一轮
    ├── history/               历次最终文档：每轮开始前上一轮移到这里
    └── A股 银行股息收集-2026-10-31_21-30-00.pdf 最新最终文档（或 .png）
```

目录骨架、执行要求与输出约定不在任务目录里：它们是插件注册的 `atan-daily-run` skill，所有任务共用；执行时由指令要求会话先加载它。

## 6. 飞书机器人

- **只发不收**：只调用飞书的「发消息」「上传文件」「上传图片」接口；不订阅事件、不建长连接、不需要公网地址。
- **权限只有两条**：`im:message:send_as_bot`（发消息）与 `im:resource`（上传文件/图片）——扫码后的确认页上就这两项。
- **密钥只在本机**：App Secret 存进 DSH 凭据库，`bots.json` 只记掩码后的 app_id 与扫码人 open_id；任何接口响应都不会回传 secret。
- **发送目标只有一个**：扫码人的私聊。要让别人接收，就让对方扫码接入自己的机器人。
- **每条报告带任务名**：每条报告先在对话里发一行「任务名 · 报告名」，紧随其后才是报告内容；文件名（也是飞书里的文档名）保持不变。
- **PNG 直接显示**：PNG 走飞书图片消息（`im/v1/images` + `msg_type=image`），在聊天里直接展开；超过 10MB 或图片上传失败时回退成文件消息。PDF 仍走文件消息。
- **推送失败不影响任务**：报告照常落盘，失败原因写进运行日志（事件 `im.push`）。
- **移除只管本机**：卡片上的「移除」只删本机记录与凭据，飞书里的应用还在，需要手动停用/删除。

### 手动停用与删除应用

| 想做什么 | 路径 | 谁来做 |
| --- | --- | --- |
| 停用应用 | 管理后台 → 工作台 → 应用管理 → 找到该应用 → 配置 → 基本信息 → 把「已启用」改成「停用」 | 企业管理员 |
| 删除应用 | 开发者后台 → 打开该应用 → 凭证与基础信息 → 页面底部「删除应用」 | 应用所有者 |

飞书开放平台没有给「扫码接入」这类应用留自动停用的口子：停用要走 `admin:app.enable:write` 管理员权限，而本插件只申请发消息与上传文件两条权限，所以这一步只能在后台手动完成。已发布的应用要先停用才能删除；删除不可恢复。

## 7. 运行与调度机制

```text
浏览器（列表 / 新建 / 启停 / 执行一次）
        │  HTTP
        ▼
Host：cron 定时 → 到点 → 归档上一轮最终文档 → 新建或复用会话 → 送入指令
      → 会话加载 atan-daily-run skill → 按契约取数 → 写 .meta/build/<runId>/report.json
      → Host 校验契约 → 按任务格式渲染 PDF/PNG → 记运行记录 → 推送
```

执行发生在 Host 侧，所以关掉页面不影响定时任务。每次执行固定使用 `deepseek-flash` 模型，按任务设置的权限级别（默认「工作区内修改」）、免审批方式自动运行；需要工作区外读写时请在编辑抽屉里改为「完全权限」，并先在测试选题上验证任务细节再交给定时任务。

- 执行指令只有一行：只给任务身份、`runId` 与本轮报告文件名，然后要求先加载 `atan-daily-run` skill；路径、工具顺序、契约修订与结束语格式都只写在 skill 里，一处维护。
- 模型只写 `.meta/build/<runId>/report.json`：PDF/PNG 由插件渲染，模型碰不到版式，也就无从走样。
- 每轮结束时回复固定成两块：一张「新增文件表」（数据契约 / 脚本 / 缓存 / 清单）和最后一行「报告：<文件名>」，不写结论与过程说明。
- 到点判断允许晚触发：机器休眠后迟到仍算这一次；重启只补最近一次错过的执行。
- 无执行时间的任务只能手动执行；停用的任务不参与定时。
- 不同任务同时到点会同时开跑，不设并发上限；模型配额、机器负载和飞书推送频率请自行评估，再决定同时启用多少任务。
- 同一个任务不会重叠执行：上一轮还没结束时到点的那次记为跳过。
- 执行失败不自动重试，错误写入 `lastError`，下次按计划继续；单轮默认超时 1800 秒。
